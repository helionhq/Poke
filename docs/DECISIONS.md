# Decisions

Defaults picked while building, where the brief left room. Newest last. Locked decisions from the
brief (section 2) are not repeated here.

| # | Area | Decision | Why |
|---|---|---|---|
| 1 | Tooling | **TypeScript 6.0.3**, not 7.0. | typescript-eslint 8.74 supports `typescript <6.1`. Revisit when it supports the Go-based TS 7. |
| 2 | Storage | `poke.db` uses **`node:sqlite`** with hand-written SQL migrations, not Drizzle + better-sqlite3. | No native module to compile on the server or in CI, the same SQLite build Pi Durable uses, FTS5 included. Drizzle has no `node:sqlite` driver in 0.45. |
| 3 | Packages | Workspace packages export TypeScript source under a `@poke/source` export condition, and built `dist/` for everything else. | vitest, Metro and `node --conditions=@poke/source` read source directly (no build before tests); production runs compiled JS. The name is scoped so it can't collide with a generic `source` condition that a third-party package or tool might define. |
| 4 | Domain | Repository ports are **synchronous**. | `poke.db` is embedded SQLite owned by one process; sync calls make "save entity + append event" one transaction. |
| 5 | Domain | `packages/domain` may use global types (`AbortSignal`) but imports nothing. | Both Node and React Native provide them; the dependency rule is about imports. |
| 6 | Events | `message.delta`, `agent.activity` and `task.progress` are **live-only** (no seq). Persisted events carry full snapshots (`message.updated` etc.). | Persisting every token is wasteful; a reconnecting client replays persisted events from `since`, then gets a snapshot of in-flight messages. |
| 7 | Boundaries | Enforced with **dependency-cruiser** (`pnpm boundaries`, CI). | Works on resolved paths across pnpm symlinks; rules in `.dependency-cruiser.cjs`. |
| 8 | Layers | `application` may import `blocks` and `agent-core` as well as `domain` and `contracts`. | Both are pure, platform-agnostic packages (catalog + prompts/tool specs). |
| 9 | Docs | The full brief is kept at `docs/BRIEF.md`. | It is the spec every milestone is checked against. |
| 10 | Server | Two Fastify apps over one kernel: **public** on 127.0.0.1:7070 and **admin** on a 0600 unix socket (`~/poke/run/admin.sock`). The admin socket needs no token. | The CLI runs as Poke's own user, which already owns `~/poke`. A socket can't be reached through the tunnel, so `/admin/*` never exists on the TCP listener. |
| 11 | CLI | When the server is down, the CLI opens the kernel in-process (same `poke.db`). | `poke setup`, `login`, `config` and `model` must work before the server is installed. SQLite WAL and a busy timeout keep the two safe if both run. |
| 12 | Auth | Device tokens are `pk_` + 32 random bytes, stored as sha256. The WebSocket also accepts the subprotocol `poke.bearer.<token>` next to `poke.v1`. | React Native's WebSocket can't always set headers. The server only ever echoes `poke.v1`. |
| 13 | Pairing | The QR encodes `poke://pair?d=<base64url JSON {v:1,url,code}>`. Codes are `XXXXX-XXXXX` from a 31-character unambiguous alphabet (~50 bits, rejection-sampled), single use, 10 minutes. | Scannable by the iOS camera (deep link) and typeable by hand. |
| 14 | Events | WS resume replays at most **5 000** events. Further behind (or ahead, after a restore), the server sends `hello.reset` and the client refetches the thread. | Bounded reconnect cost; the thread endpoint is the faster path after a long absence. |
| 15 | Tests | vitest resolves with the conditions `@poke/source, node, development` (not `import`). | With `import`, `ws` resolves to its ESM wrapper and `@fastify/websocket` (CJS) breaks. |
| 16 | Share | `POST /v1/share` takes JSON `{text,url,urls,note}` or multipart (files + fields) with a share-scope token. | The iOS Shortcut can send either; the scoped token limits what a leaked Shortcut can do. |
| 17 | Compaction | Claude: threshold compaction is Claude Code's own, with `CLAUDE_CODE_AUTO_COMPACT_WINDOW` = the budget (≥100K). Claude Code's `idleCompaction` setting is **off**; Poke runs idle compaction itself by sending `/compact <instructions>` at cache lifetime − 10 min, only on a 1-hour cache and above `context.idleMinTokens`, once per idle period, cancelled by any new input. Pi: Pi's compaction, with `modelOverrides` capping a larger window at the budget; idle compaction for Poke on Pi only when `context.idleCompactPi` is on; never for executors or side chats. | Brief 5.4. Built-in idle compaction inside a long-lived streaming session isn't documented; Poke's own timer is predictable and testable. |
| 18 | Compaction | The PreCompact hook returns Poke's summary instructions (as `systemMessage`) when Claude Code compacts by itself. Manual and idle compactions send the instructions explicitly with `/compact`. | In CLI 2.1.332, successful PreCompact hook output is joined into the compaction's custom instructions (read from the binary, checked for command hooks). Whether an SDK callback hook's output is picked up the same way needs one live check with a real token; the explicit `/compact` paths don't depend on it. |
| 19 | Models | Claude models are listed live with the Agent SDK's `supportedModels()` (Claude Code starts, no prompt is sent, cached 10 min). Without a login or offline, a curated list stands in: Opus 5.5, Sonnet 5.5, Haiku 5.5 (1M context, effort low…max). A live model the list doesn't know gets a 200K window. | Brief 6.1. The curated list is a catalog, not a default; nothing is ever picked for the user. The small window keeps the budget safe for unknown models. |
| 20 | Steering | On Claude, input that arrives mid-turn is pushed into the live query with `priority: "now"`. If the result comes back while a steer hasn't been echoed (`isReplay`), the turn waits up to 5 s for the run it starts. On Pi, `submit` with `whenBusy: "steer"`, `whenIdle: "reject"`; a rejected steer becomes the next turn. | No message is lost between "turn ended" and "steer accepted". |
| 21 | Logins | Qwen keys are checked with a one-token request to the plan's own endpoint (pi-ai's base URL; `qwen3.6-flash` or the first model); a 429 counts as valid. Claude setup tokens get a format check only (`sk-ant-oat…`). The CLI never takes a secret as an argument: it prompts, or reads `--stdin`. | Brief 21: validate before saving. A Claude check would start a session; a bad token shows up on the first turn as a login note. Arguments end up in shell history and `ps`. |
| 22 | Models | A role can only be set to a provider that is logged in. `poke model` offers the login inline ("log in…"). | Brief 6.2. A model that can't run is worse than "not set". |
| 23 | Logins | `poke login anthropic` runs the Claude Code binary that ships in the Agent SDK's platform package (`@anthropic-ai/claude-agent-sdk-<platform>-<arch>`) with `setup-token`, using the same environment allowlist as the runtime, then asks for the token it printed. | Nothing extra to install. The terminal UI needs a real TTY, so Poke doesn't capture its output; pasting is reliable. |
| 24 | Agents | `ask_poke` parks the executor with a Pi Durable sleep on the signal `poke.need`, keyed by the need id; Poke answers with `send_to_agent` and the agent's id, which resolves the signal. Answers to a need that's no longer waiting report "not found". | Brief 5.2: the question survives restarts (durable.sqlite) and costs no tokens while waiting. |
| 25 | Traces | One trace per Poke turn that starts or messages agents, in its own Poke message (a `trace` part) under the reply. The report turn writes Poke's answer into that message when it has no text yet; otherwise a new message. | The thread reads "On it" → trace → result, as in the designs. |
| 26 | Poke | Inputs that queue up while Poke is busy (messages that couldn't steer, agent reports, questions) run as one turn with one `<context>` block. Messages sent while Poke has no model get a single "Poke has no model yet" note and are answered once a Poke model is set. | Brief 6.1 ("messages are still saved and get answered once a model is set"). |
| 27 | Context | A fresh session (first boot, a runtime switch, a lost session) starts with a digest: the latest compaction summary, the recent turns verbatim (~60K characters), and running agents. The Honcho card joins in milestone 7. | Brief 5.4. The full thread stays in `poke.db`; `search_thread` reaches the rest. |
| 28 | Redaction | The redaction set is every vault system secret and every entry's secret fields, decrypted once per vault change. Each value is also matched as base64, base64url, URL-encoded and JSON-escaped (values shorter than 6 characters are skipped). | Brief 10. Decrypting on every tool call would be slow; the vault's change hook keeps the set current. |
| 29 | Side chats | Side chats live in memory (at most 5 open). On Pi each gets its own in-memory harness that shares the tool registry. `POST /v1/sidechats/:id/messages` returns once the message is accepted; the reply streams over the event socket. | Brief 5.6: nothing is saved, and a long reply must not hold an HTTP request open. |
| 30 | CLI | `apps/cli/src/main.ts` is a launcher: it filters node:sqlite's ExperimentalWarning, then dynamically imports the CLI (`cli.ts`). | Static imports load node:sqlite before any code runs, so the filter has to come first. |
| 31 | Blocks | The server stores only `idle`/`sent` for drafts and `pending`/`saved` for secret requests; `editing` and `filled` are app-local states. | A typed secret must never reach the server before Save, and an edit in progress isn't worth a round trip. |
| 32 | Blocks | Every action needs a `clientActionId` (8–80 characters). The first answer (including results like a sign-in URL) is stored by id; a retry gets it back with `duplicate: true`. The same id for another block or action is a 409. Actions on one block are serialised. | Brief 9.3 (idempotent). A double tap or a retried request on a bad connection can't book or save twice. |
| 33 | Blocks | A `secret_request` saves to vault entry `vaultName`, under a field named after its type (`password`, `api_key`, `code`, `number` for a card, `value` for text). New entries take the matching vault kind; an existing entry gets the field merged in. Codes are ephemeral (10 minutes). The resolution and the agent get `{status, vaultName, placeholder}`. | One block shape covers logins, API keys and codes (9.1); the agent needs the exact placeholder to use. |
| 34 | Blocks | Agents' secret and connection needs are attached by the server after Poke's turn about them ends: under Poke's reply, or in a Poke message of their own if there's no reply. | Brief 9.4. The block always appears, even when Poke has no model or the turn fails, so a parked agent is never stranded. |
| 35 | Blocks | Choices are answered as the user's own message (origin `user`); everything else on Poke's blocks reaches Poke as a `<block_action>` system input. Draft edits are saved silently; the final text goes to Poke when the primary action is tapped. | Brief 9.2: picking "sends the label as the user's message". Edits alone don't need a turn. |
| 36 | Blocks | Blocks owned by a task expire when the task ends (`task.completed`), and on boot when the task no longer waits on that need. | An answer to a need nobody is waiting for would be lost. |
| 37 | Blocks | `card` is a flat map of nodes with a `root`, each node used once, at most 6 levels, 60 nodes, 8 buttons, 8 inputs, 16 KB. Images must be https; logos are an app id or a domain. | Brief 9.1: a small, validated tree of safe primitives modelled on A2UI-style adjacency lists. |
| 38 | Blocks | Actions whose effect belongs to a later milestone (`connect`, deciding a `tool_approval`) return 503 and leave the block unchanged until a `ConnectionStarter` / `ApprovalDecider` is plugged in. | The ports are in place; nothing pretends to have connected or approved. |
| 39 | Vault | Placeholders are filled in only for tools that act outside Poke: Pi's `bash`, `write` and `edit`, and gateway tools registered with `resolveSecrets`. Bash gets environment variables, quoted to expand where the placeholder stood (`"${V}"`, `${V}` inside double quotes, `'"${V}"'` inside single quotes). | Brief 10. A secret resolved into `send_to_agent` would land in another model's context; on a command line it would show in `ps`. Quoted heredocs don't expand variables, and the executor prompt says so. |
| 40 | Vault | Redaction labels are `[vault:<entry>]` for entry secrets and `[vault:system]` for provider credentials. | Brief 10 asks for the vault name; provider credential names are internal. |
| 41 | Vault | Face ID is checked on the server with an Ed25519 key enrolled at pairing (private key in the Keychain behind biometrics, public key on the server) and a single-use challenge per action and entry. | `expo-local-authentication` alone is a local yes/no the server can't trust. A signed challenge proves the scan happened on that phone, for that action. Enrolment rides on the one-time pairing code, so a leaked token can't enrol a key. |
| 42 | Vault | Expired one-time codes are swept every minute by the agent stack. | Brief 10: "wiped after use or after 10 minutes". |
| 43 | Approvals | `ApprovalService.gate(ctx, input, run)` is the one entry point for Executor-gated calls: a matching rule runs `run` at once; otherwise the agent parks on an `approval` need and `run` gets the outcome when it resumes. The Executor bridge (milestone 6) supplies the input and resumes or declines Executor inside `run`. | Keeps Executor's protocol out of the approval logic and makes the whole flow testable now. |
| 44 | Approvals | An approval's block is a `draft` (sends), an `action` card (bookings, purchases) or a `tool_approval` (anything else), chosen by the caller as `presentation`. The block reaching its final state is the decision: draft sent → allowed (with the edited text as `final`), action confirmed → allowed, changed or cancelled → denied (with the note), tool_approval allowed or denied. | Brief 12.1. |
| 45 | Approvals | Rules are created only from a real approval's offer (`{description, constraint?}`), never by an agent or through the API; the app can list and delete them. Conditions are a JSON-logic subset (var, comparisons, and/or/!, in) with no type coercion. | Brief 12.4. A rule must mean exactly what its plain words say. |
| 46 | Approvals | Approvals and their blocks expire when their task ends, and on boot when the task no longer waits on them. Drafts and action cards gained an `expired` state for this. | Nobody can act on an OK for work that stopped. |
